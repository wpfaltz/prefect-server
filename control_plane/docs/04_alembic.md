# Componente: Alembic

## Visão Geral

O **Alembic** é a ferramenta de **migração de schema** utilizada para gerenciar a evolução do banco de dados do control-plane. Ele garante que as tabelas do Key Vault (principals, secrets, secret_mapping, audit_log) e suas views sejam criadas e atualizadas de forma controlada, versionada e reprodutível — tanto em desenvolvimento quanto em produção.

O Alembic é executado **automaticamente** no startup do container `fastflow-control-plane`, antes do servidor FastAPI subir, através do comando `alembic upgrade head`.

---

## Como foi Implementado

### Configuração

O Alembic é configurado pelo arquivo `alembic.ini` na raiz do backend, que aponta para o diretório `alembic/` contendo o `env.py` e as migrations versionadas. A URL do banco **não é hardcoded** no `alembic.ini`; em vez disso, o `env.py` sobrescreve dinamicamente a URL lendo a variável de ambiente `CONTROL_PLANE_DB_URL`.

### Execução no Docker

No `docker-compose.yml`, o container `fastflow-control-plane` executa:

```yaml
command: >
  sh -c "alembic upgrade head &&
         uvicorn app.main:app --host 0.0.0.0 --port 8008"
```

Isso garante que todas as migrations pendentes sejam aplicadas **antes** da API começar a receber requisições.

## Arquivos nos quais se baseia

| Arquivo | Função |
|---|---|
| `alembic.ini` | Configuração principal do Alembic (caminhos, logging, separador de paths). A `sqlalchemy.url` é um placeholder — o valor real vem do `env.py`. |
| `alembic/env.py` | Script de ambiente do Alembic. Define `get_url()` para ler `CONTROL_PLANE_DB_URL`, configura o `target_metadata` a partir do `Base` declarativo e implementa os modos offline/online. |
| `alembic/versions/0001_init_vault.py` | **1ª migration**: cria as tabelas `principals`, `secrets`, `secret_mapping`, `audit_log`, seus índices e a VIEW `v_secret_resolution`. |
| `alembic/versions/0002_secrets_assign_level.py` | **2ª migration**: adiciona a coluna `assign_level` (String(16), default "reader") na tabela `secrets`. |
| `app/db/session.py` | Fornece a classe `Base` (DeclarativeBase) cujo `metadata` é utilizado pelo Alembic para autogenerate. |
| `app/db/models.py` | Modelos ORM registrados no `Base.metadata` — o Alembic compara esses modelos com o banco para detectar diferenças. |

## Principais Funções

### `alembic/env.py`

| Função | Descrição |
|---|---|
| `get_url()` | Lê a variável de ambiente `CONTROL_PLANE_DB_URL` e retorna a URL de conexão. Levanta `RuntimeError` se não configurada. |
| `run_migrations_offline()` | Executa migrations sem conexão real com o banco — apenas gera SQL. Útil para gerar scripts de migração para revisão manual. |
| `run_migrations_online()` | Executa migrations com conexão ativa. Cria engine a partir da configuração, conecta-se ao banco e aplica as migrations dentro de uma transação. |

### Migrations

| Migration | Descrição |
|---|---|
| `0001_init_vault` | **upgrade()**: Cria tabelas `principals`, `secrets`, `secret_mapping`, `audit_log`, índices e a VIEW `v_secret_resolution`. **downgrade()**: Remove VIEW, índices e tabelas. |
| `0002_secrets_assign_level` | **upgrade()**: Adiciona coluna `assign_level` à tabela `secrets`. **downgrade()**: Remove a coluna. |

## Principais Variáveis de Ambiente

| Variável | Descrição |
|---|---|
| `CONTROL_PLANE_DB_URL` | URL de conexão SQLAlchemy com o PostgreSQL. É lida pelo `env.py` e usada tanto pelo Alembic quanto pela aplicação FastAPI. Formato: `postgresql+psycopg://user:pass@host:port/db`. |

---

## Relacionamento com outros componentes

| Componente | Tipo de relação |
|---|---|
| **PostgreSQL** | **Alvo direto** — o Alembic conecta-se ao PostgreSQL para criar/alterar tabelas e views. |
| **FastAPI (Control Plane)** | **Pré-requisito** — o Alembic roda antes do servidor subir (`alembic upgrade head && uvicorn ...`). A aplicação FastAPI espera que as tabelas já existam. |
| **Key Vault** | **Define o schema** — todas as tabelas necessárias ao Key Vault (principals, secrets, secret_mapping, audit_log, v_secret_resolution) são criadas e evoluídas pelo Alembic. |
| **Modelos ORM** | **Fonte de verdade** — os modelos em `app/db/models.py` são a referência que o Alembic usa para comparações e autogenerate de novas migrations. |
| **Google OAuth** | **Sem relação direta** — o módulo OAuth não utiliza tabelas gerenciadas pelo Alembic. |
| **Streamlit** | **Sem relação direta** — o dashboard não interage com o Alembic. |
